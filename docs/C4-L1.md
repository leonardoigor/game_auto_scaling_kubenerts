# C4 – Nível 1: Contexto

- Sistema: Jogo 2D stateless em tempo real sobre WebSockets, com estado centralizado em Redis e execução em Kubernetes.
- Usuários: Jogadores (browser) usando o cliente Web para enviar inputs e receber atualizações.
- Sistemas externos:
  - Redis: Pub/Sub e armazenamento de snapshots por sala.
  - Kubernetes API: Escalonamento do `gateway` via serviço `matchmaker` quando o pod atinge capacidade e redução automática quando um pod permanece ocioso por 20s.
- Conceitos de jogo:
  - Buffs de mapa: itens com letras (`V`,`A`,`M`,`D`) coletáveis, conferem vantagens temporárias por 20s, acumuláveis, e respawnam ao expirarem.
    - `V`: velocidade própria ↑ (×1.5 por instância)
    - `A`: ataque próprio ↑ (×1.5 por instância)
    - `M`: velocidade inimiga ↓ (×0.7 por fonte, raio 100px)
    - `D`: ataque inimigo ↓ (×0.7 por fonte, raio 100px)
- Relacionamentos principais:
  - Cliente ↔ Gateway (WebSocket)
  - Gateway ↔ Redis (Pub/Sub: `room:{id}:in` e `room:{id}:out`)
  - Worker ↔ Redis (Pub/Sub + KV: estado e players por sala)
  - Matchmaker ↔ Kubernetes API (REST) e Redis
