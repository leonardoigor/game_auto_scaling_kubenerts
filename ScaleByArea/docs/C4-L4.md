# C4 – Nível 4: Código

## Protocolo de Mensagens
- `join`: `{ type: "join", payload: { playerId, roomId } }` → gateway responde `assign_room` com `regionId`.
- `assign_room`: `{ type: "assign_room", payload: { roomId, podId } }`.
- `input_move`: `{ type: "input_move", payload: { dir: { x, y } } }` → gateway publica em `region:{id}:in`.
- `input_attack`: `{ type: "input_attack", payload: { angle } }` → worker cria projétil.
- `ping`/`pong_gateway`: medição de latência cliente↔gateway.
- `ping_worker`/`pong_worker`: medição de latência cliente↔worker; `ping_worker` também garante spawn de jogador.
- `latency_update`: broadcast de RTT por jogador.
- `handover`: `{ playerId, fromRegionId, toRegionId }` para transferir controle ao atravessar fronteira.
- `region_creating`/`region_created`: sinalizam criação dinâmica de região alvo.
- `state_update`: `{ regionId, players: [...], projectiles: [...], buffItems: [...], ghostPlayers: [...], zones: [...] }`.
- `give_buffs`: solicita ao worker aplicar `size` buffs aleatórios ao jogador.
- `leave`: remove jogador do estado e do conjunto `region:{id}:players`.

## Estruturas de Estado
- Jogador: `{ x, y, vx, vy, speed, podId, hp, maxHp, dead, killerId, lastAttackTs, buffs[] }`.
- Região: `{ players: Map<playerId, Player>, projectiles: Array<Projectile>, buffItems: Array<BuffItem>, lastUpdate }`.
- Projétil: `{ x, y, vx, vy, ownerId }`.
- BuffItem: `{ id, x, y, type }`; Buff ativo: `{ type, expiresAt }`.

## Algoritmos
- Movimento: integração por `dt`; região destino por `floor(x/CELL_W)`,`floor(y/CELL_H)`; clamp às bordas durante criação da região alvo.
  - Referências: `worker/index.js:203–227`
- Ataque: valida cooldown e cria projétil com velocidade/ângulo.
  - Referências: `worker/index.js:364–369`
- Física de projéteis: atualiza posição; remove ao sair dos limites da região; colisão jogador-projétil (`<= 12px`); aplica dano com multiplicadores de buffs.
  - Referências: `worker/index.js:263–279`
- Ghosts: exporta jogadores próximos das bordas e importa de vizinhos cardinais.
  - Referências: `worker/index.js:168–181`, `worker/index.js:183–196`
- Buffs:
  - Coleta: raio 14px; adiciona `{ type, expiresAt = now + 20000 }`.
    - Referências: `worker/index.js:246–254`
  - Expiração/Respawn: remove expirados e respawna itens.
    - Referências: `worker/index.js:110–128`
  - Multiplicadores e auras: `V`,`A` e `M`,`D`.
    - Referências: `worker/index.js:145–166`
  - Aplicação via console: `give_buffs` no cliente injeta buffs aleatórios no worker.
    - Referências: `client/main.js:404–409`, `gateway/index.js:167–178`, `worker/index.js:387–401`

### Buffs – Detalhamento dos Efeitos
- `V` (Velocidade+): multiplica a velocidade do jogador por `1.5` por instância (empilhável).
- `A` (Ataque+): multiplica o dano do jogador por `1.5` por instância (empilhável).
- `M` (Movimento-, aura): para cada fonte em um raio de `100px`, multiplica a velocidade dos inimigos por `0.7` (empilhável).
- `D` (Ataque-, aura): para cada fonte em um raio de `100px`, multiplica o dano dos inimigos por `0.7` (empilhável).
- Cálculo do dano com buffs: `damage = floor(base * attUp * attDown)`, com `base = floor(0.2 * maxHp)`, `attUp` produto de `A`, `attDown` produto de `D`.
  - Referências: `worker/index.js:172–176`
- Publicação de estado: por tick e imediatamente após ataque para baixa latência.
  - Referências: `worker/index.js:107–110`, `worker/index.js:140–146`

## Operação
- Kubernetes:
  - Services: `gateway` (NodePort `30080`), `matchmaker` (NodePort `31400`), `redis` (ClusterIP `6379`).
  - Deployments: `gateway`, `worker`, `matchmaker`, `redis`.
  - RBAC: Role/RoleBinding para o `matchmaker` operar Deployments.
- Scripts: `scripts/deploy.ps1`, `scripts/destroy.ps1` (remove também `worker-region-*`).
- Lifecycle ocioso do `gateway`: escala para baixo após 20s sem jogadores.
  - Referências: `gateway/index.js:202–221`
- Lifecycle ocioso do `worker`: encerra apenas sem jogadores locais e globais por 20s.
  - Referências: `worker/index.js:318–336`
- Redis viewer: `redis-commander` (NodePort `30881`).
  - Referências: `k8s/redis-commander.yaml`, `scripts/deploy.ps1`, `scripts/destroy.ps1`.

## Observações
- Autoritativo por região: workers controlam `region-<col>-<row>`.
- Câmera e minimapa: cliente segue o player; minimapa exibe regiões, frutas, players e seta direcional.
- Ghost zone: efeitos e visão inter-região são condicionados à ghost zone.
- Anti-spam de criação: flag `region:<id>:creating` com TTL evita recriações.
- Balas não atravessam fronteiras: removidas ao sair dos limites da região.
